01决策摘要：已确认 / 建议 / 待确认

本文件是供研发评审的待确认方案，不是已批准可直接开工的 PRD，也不包含产品实现。条目分四类标注：已确认 有本次只读核查的本地文件支持；用户已明确需求 是需求方向、非实现批准；建议 是技术与实现方案，待评审批准；待确认 取决于评审拍板，集中列在 §10。

推荐结论（建议）

以现有桌面骨架为基础，单人本地优先，先做无网络也能闭环的部分：自由文本建档、资料库（文件 / 链接 / 笔记）、手工录入财务与自定义指标、可改的判断草稿、仅追加的正式判断、立即可用的指标看板与本地一致性备份。自动采集只在来源许可依据明确后按分级接入，首验 macOS ARM64；Web 与其他平台现状保留，行情、自动估值、AI 聊天 / 报告 / 模型配置全部后置为未来插件位。

已确认 本地现状事实

  • pnpm monorepo：apps/web、apps/desktop、packages/valuation、packages/content-schema。
  • 桌面端仅工作台（app_info 原生连接三态检查）与手动 DCF 计算页；输入不上传、不保存、离开清空。
  • Rust 仅 tauri / serde / serde_json，一个 app_info 命令；权限仅 core:default，未授予文件、网络、shell。
  • macOS ARM64 本地 .app/DMG 已构建并做基础窗口验证（精确范围见 §2.1）。

用户已明确需求（方向，非实现批准）

  • 公司范围：A 股、港股、美股、非上市公司均可建档。
  • 采集对象：定期财务、公司公告、新闻三类。
  • 仅使用免费源；不含 AI 聊天 / 报告生成 / 模型配置调用，不含行情与自动估值采集。
  • 以上为需求方向，须评审明确确认后才进入实现。

建议 技术与实现方案（待批准）

  • SQLite 本地库、资料库、指标观测、可配看板、不可变正式判断与证据快照、本地备份恢复。
  • 来源准入分级、采集状态与幂等恢复、Rust 窄 Tauri 命令（SQLx / Tokio / reqwest）、TanStack Query / ECharts / Tiptap、运行时调度等技术方案。
  • 阶段编排：P00 基线 + P01–P13 分阶段路线与每阶段验收（§9）；依赖可真并行，编号不强制开发排队，条件源不承诺必达。

待确认 需评审拍板

  • 四项关键确认见 §10；未确认前仅保留为建议，不实施。
口径提醒：某免费源首次能访问，不等于获得稳定、可持续的授权；本方案不把"首次访问成功"写成稳定授权，所有外部源的条款与可访问性均标注为"待接入验证"（见 §3、§5）。

03公司范围与三类数据覆盖矩阵

3.1 公司与证券模型（建议）

  • 以内部独立公司 ID 作为公司主键，支持自由文本建档，登记市场、注册地等基础信息；不以 ticker 作为公司主键。
  • 证券单独建模为 listing：A 股 / H 股 / ADR 等多个证券可对应同一公司；退市、换代码、ADR 比例变化都挂在证券记录上，不污染公司主体。
  • 非上市公司照常建档，无证券记录，财务与资料以人工录入为主。
  • 初始跟踪名单后续试点时再填，不阻断本方案评审。

3.2 来源准入与数据形态分开标注

本矩阵把两件事分开：来源准入等级（能不能从该来源取、取到什么程度）与数据形态（保存原始文档还是只存结构化值），二者不混为一谈。准入三级：

  • A 已文档支持 · 待接入验证：有官方文档支持、免费无 key（如 SEC submissions / companyfacts），仍需目标公司与本机网络接入验收，条款与限频在接入时核对。
  • B 条件适配：需人工确认许可、格式或额外条件后才可取。
  • C 仅人工：不自动获取，由本人手工录入或粘贴。

数据形态另标：原始文档（许可允许时落盘保存）/ 结构化值（人工审核后入库的数值与字段）。

市场定期财务公司公告新闻

显式取舍：本轮未核实到可直接承诺免费统一标准化官方 API 的市场 / 数据类，属于需用户同意的来源缺口，不是"已自动覆盖"。手工录入、手工导入、人工链接不等于自动采集验收通过；未覆盖的自动需求在 §9 保留降级验收行，不以手工路径顶替自动验收。

05采集策略、归因版权、状态与恢复

5.1 来源准入与自动下载的许可依据（建议）

  • 自动访问 / 存储任何内容（含元数据）前，必须在来源登记中记录许可依据（官方条款原文或公开披露说明）；robots 只是需附加遵守的技术规则，不是许可依据。无许可时连元数据的 API 访问 / 存储也不自动进行，只能人工书签，不得借"仅元数据"绕过闸门。
  • 准入等级（A/B/C，见 §3.2）描述"能不能取"；原始文档 / 结构化值描述"存什么"，二者独立标注。
  • 条款与用途限制以官方原文（§11）为准；本机连通、目标公司低频验收与 key 留存条款仍为待接入验证，不得在接入前写成"已授权可抓取"。
  • 免费套餐 / 公开渠道的用途限制，需在接入验收时区分"个人本地日常研究"与"商用 / production"场景并按条款如实标注；证据不足时既不写成"个人使用即不得进入产品"，也不默认全部可用。

5.2 归因与版权

  • 每条记录保存：来源名称、原始 URL、来源发布时间 published_at、本机采集时间 first_seen_at / collected_at、许可标记、内容 hash。
  • 新闻默认只存元数据（标题 / 来源 / 原链接 / 时间），不默认抓取全文；全文仅在许可允许时归档。
  • URL + 内容 hash 不能被称为"全文快照"；证据必须显式标 full（已存原文）或 metadata_only（仅元数据），写明缺口。

5.3 调度策略（建议）

  • 仅在应用运行时按到期时间补抓；应用退出或关机不跑，不注册后台常驻服务、不开机自启。
  • 下次启动时补上错过的到期任务；补抓顺序与限频由任务记录控制，避免集中请求。

5.4 任务状态与失败恢复（建议）

状态含义恢复 / 去向
排队 / 运行中已登记待执行或正在执行。应用退出后标记为未完成，下次启动重新排队。
成功按准入等级完成归档或元数据入库。记录来源、时间、hash；重复运行按 URL + hash 幂等去重，不产生重复记录。
失败网络、格式或解析错误。保留错误原因，可手动重试；不自动无限重试。
跳过（许可不足）许可依据缺失，或不允许该级别的自动访问 / 存储。有元数据许可才存元数据；连元数据也无许可时仅人工书签，记录原因，不伪装成已归档。

5.5 分来源准入细则（建议）

来源已核实要点准入与边界

06数据模型与不可变判断、证据、财报修订

本节为领域模型建议，只列实体与关键规则，不写建表语句；本期公司领域模型留在 desktop 内部（§7）。

6.1 核心实体（建议）

实体职责关键规则
Company 公司内部公司 ID、名称、市场、注册地、自由简介、自定义标签。ID 独立生成，不使用 ticker 作主键；可关联资料、指标、判断。
Listing 证券挂在公司下的 A / H / ADR 等证券、代码、状态。多证券对一公司；退市换码只改证券记录。
FinancialFact 财务值一条带完整口径的财务数值（见 6.2）。带审核状态；缺失不等于 0；保留修订版本。
MetricDefinition 指标定义内置原始项映射（直接引用已审核 FinancialFact，不复制）+ 少量固定纯函数（派生，公式 / 口径写死、版本化）；自定义数值 / 文本指标定义。无用户自定义计算，不建公式 DSL；派生结果保留输入版本与公式版本。
MetricObservation 指标观测自定义数值 / 文本指标在某公司某期间的取值、口径、审核状态与来源指针。未审核值默认不进已审核趋势，可切待核视图灰显；数值缺值留空、图上断点；文本仅卡片展示、不进趋势图。
Material 资料库条目手动文件 / 链接 / 文本笔记，可挂标签、公司、归档状态。本人自写内容不受第三方撤销隔离规则限制（§8.2）。
MaterialVersion / Attachment资料版本与附件；内部复制落盘或外部引用二选一记录。原件迁移 / 重命名后，内部复制仍可用，外部引用记录原位置。
Tag 标签跨公司、资料、指标、判断的自由标签。用于搜索与分组，不承担层级权限。
Announcement 公告公司公告 / 备案文件的元数据与可选原文引用。原文仅许可允许时归档；标 full / metadata_only；可带 restricted 指针。
NewsItem 新闻线索标题 / 来源 / 原链接 / 时间。默认 metadata_only，不默认抓全文；可带 restricted 指针。
JudgmentDraft 判断草稿本人可反复修改的自由正文判断。可改可删；证据可选引用，缺证不阻止保存或转正式（见 6.5）。
JudgmentOfficial 正式判断转正式后的判断版本链。仅追加，不可回写；修订复制新版本，可填可选修订原因。
Evidence 证据结构化采用值与版本引用，可选归档文件。自动采集不得改写已正式判断与证据快照；可带 restricted 指针。
TakedownEvent 撤销事件最小留痕：关联负载 hash、来源、原因、时间、许可状态。只追加不覆盖；非核心路径、非日常审批中心（§6.4）。
SourceLicense 来源登记准入等级、许可依据、限频与降级记录。无依据不得自动下载。
CollectionRun 采集任务一次采集的状态、错误、hash 与时间。幂等去重；失败 / 跳过可追溯。
DashboardConfig / CardConfig看板布局、卡片显隐 / 排序 / 分组与所选指标。本地配置，重启保持；不做低代码搭建器。
BackupManifest 备份清单备份范围、文件清单与 hash。恢复先校验清单一致性（§8）。

6.2 财务值最小字段（建议）

每条财务值至少携带：币种、单位、期间起止、财年、季度或累计（Q1 / 半年 / Q3 / 全年）、合并口径（合并 / 母公司）、会计准则、源字段名 + 标签、来源发布时间 published_at、首次入库时间 first_seen_at、修订版本号、审核状态。

  • 缺失字段留空并标注，不得按 0 处理；不强行做跨市场、跨口径可比。SEC companyfacts 缺某标签只表示该申报未提供该口径，不等于公司未披露该项[S1]。
  • published_at 为来源发布时间；first_seen_at 为本机首次入库时间，写入后不可变；collected_at 为本次采集时间，记在 CollectionRun 上，二者用途不同，不混同。

6.3 不可变判断与版本保留（建议）

6.4 证据规则（建议）

  • 证据保存结构化采用值与版本引用；归档文件仅在许可允许时落盘。
  • 每条证据显式标 full（已存原文）或 metadata_only（仅元数据），写清缺口；URL + hash 不等于全文快照。
  • 自动采集不改变已正式判断与证据快照；采集到的新事实只进入候选 / 新版本，由人工决定是否采用。
  • 依法撤销留痕（逻辑版本不覆盖，最小原则）：授权到期或法律要求清理时，正式人工判断的文字与版本仍不回写；仅第三方证据负载可依法删除，撤销 / 受限事件落 TakedownEvent（含内容 hash、来源、原因、时间、许可状态），证据 / 公告 / 新闻以 restricted 指针关联，并保留缺证状态。该机制只在触发清理时记录，不是核心路径必经操作，也不做用户日常审批中心。备份中的受限第三方负载不恢复，不保证所有快照永远可读。

6.5 判断书写（建议：自由正文优先）

  • 自由正文为主体：判断以本人书写的正文为主；护城河、管理层、资本配置、风险等只是可选提纲块，不强制分段、不缺项不可保存。
  • 证据可选：可引用证据与采用值版本，转正式（冻结版本）不以附证据为前提，缺证不阻断；未附证据的判断仅标注"未附证据"，由本人负责。不设强制的 Comment / Draft / Official 三流。
  • 自动保存仅限草稿与正文内批注：编辑内容本地暂存；正式冻结版只读，不进入自动保存。保存失败时保留已输入内容并显示失败 / 可重试状态，提供手动重试，离开 / 切换前先保护未保存内容，不丢字。
  • 时间线与版本差异：草稿、转正式、修订按时间排列；正式判断版本之间可查看差异；修订原因可选填，非必填。
  • 转正式后整段冻结，修订复制为新版本，不回写旧版（§6.3）。

6.6 指标与看板观测（建议）

  • 两类内置项分开处理：原始项通过映射直接引用已审核 FinancialFact，不复制数值；少量派生项走固定纯函数（内置、公式与口径预先写死、可版本化），不提供用户自定义计算、不建公式 DSL。派生结果保留所引用输入事实的版本号与公式版本号，输入修订后按新版本重算，不改写历史结果；任一输入缺口径则该项当期不展示，不强行跨准则 / 跨市场映射可比。
  • 建议首批内置清单（原始映射 / 固定派生见下表；口径来源在接入时按申报报表如实标注，无口径不展示）：
内置指标类型固定口径 / 公式说明
营收原始映射直接引用营业收入事实值。币种 / 期间随事实。
归母净利润 / 净利润原始映射分别引用归母净利润与净利润事实值，不混同。按申报口径。
经营现金流（CFO）原始映射直接引用经营活动现金流量净额。—
总资产 / 总负债原始映射直接引用资产负债表期末值。—
归母权益 / 股东权益原始映射分别引用归母权益与股东权益，不混同。—
自由现金流固定派生CFO − 资本开支（资本开支取购建固定资产 / 无形资产等支出，固定口径）。输入缺一即不展示。
ROE固定派生归母净利润 / 归母权益（期末口径，不自行年化或改平均口径）。输入缺一即不展示。
毛利率固定派生（营收 − 营业成本）/ 营收。输入缺一即不展示。
净利率固定派生净利润 / 营收。输入缺一即不展示。
资产负债率固定派生总负债 / 总资产。输入缺一即不展示。
  • 自定义数值 / 文本指标直接存 MetricObservation，由本人填值与口径，不参与内置派生。数值取值带币种、单位、期间口径，可选时间范围进图表；文本指标只以文本卡片展示，不进入趋势图。
  • 未审核值默认不进入已审核趋势；允许明确切换到待核视图灰显，与已审核值不混同；缺值留空、不按 0，图表在缺值处断点、不连线。
  • 指标定义、观测、标签与看板 / 卡片配置（DashboardConfig / CardConfig）统一存 SQLite 并进入备份；本地搜索只在本机进行，不送 Algolia、不与 Web 端互通（§7）。布局重启保持，不做任意拖拽低代码平台。

6.7 资料库（建议）

  • 条目类型：手动文件、链接、文本笔记；建议支持 PDF / 图片 / TXT / Markdown 本地预览，CSV 仅作带列映射确认的结构化导入边界。
  • 不支持的形式不强行解析，仅保留元数据与打开入口；条目、标签与归档状态存 SQLite，进入备份；标签搜索只在本机进行，不送 Algolia、不与 Web 端互通。
  • 原件去向规则：内部复制落盘的资料不受原件迁移 / 重命名影响；选外部引用的记录原位置，失效时提示重新定位。
  • 本人自写笔记与自有资料不属于"受来源限制的第三方负载"，备份可正常恢复（§8.2）。

07桌面架构与 Web 隔离、未来插件边界

7.1 推荐技术路线（建议，单一选择；以下均为拟新增，非当前已装）

推荐：网络、文件、数据库统一由 Rust 侧完成，通过窄 Tauri 命令暴露给前端；前端不同时引入 http / fs 插件。

层拟新增依赖（建议）用途取舍
Rust 原生侧SQLx（SQLite）本地库读写、迁移与校验；资料 / 指标 / 标签 / 看板配置一并入库并进入备份。不另起服务端数据库，保持单机文件库。
Rust 原生侧Tokio + reqwest异步运行时与 HTTP，采集 / 备份 / 许可检查集中在此。不使用前端 http 插件；限频、退避、UA 在原生侧统一控制。
前端TanStack Query窄命令返回数据的缓存、失效与重试状态。不引入全局状态重型库。
前端ECharts指标时间范围图表，缺值断点、待核灰显。仅渲染固定纯函数结果，无用户计算引擎。
前端Tiptap判断自由正文与可选提纲块编辑、草稿自动保存。正式冻结版只读，不进编辑器。
  • 选择理由：权限集中在 Rust 侧，便于按命令审计许可与目录边界；与现有 core:default 最小授权一致，避免前端直接持有网络与文件能力；浏览器预览不伪装原生；CSP 可保持严格。
  • 窄命令原则：每条命令只做一件明确的事（如取一家公司的公告列表、落盘一个已许可文件、写一条审核后的财务值），不在前端拼装裸请求。现有 React 19 / Vite / Tauri 2 / react-router-dom 保留，packages/valuation 手动 DCF 不动。

7.2 共享边界（建议）

  • packages/valuation 仅保留手动 DCF 计算，不拉取行情、不做自动估值。
  • packages/content-schema 局限于知识库 / 博客元数据，不强塞公司领域模型。
  • 本期公司领域模型留在 desktop 内部；未来双端真正复用时再评估提取，不预先建通用 UI 包。

7.3 未来插件边界（本期不做，仅预留接口位置）

未来扩展只预留接口边界：不建插件市场，不加载 / 执行任意第三方代码，新能力经来源登记与单独评审后以受控命令接入。

未来插件位边界说明本期状态
付费数据源许可与计费明确后，按来源登记接入，不混入免费源策略。不做
自定义数据源本人自定义格式 / 地址，经许可登记后接入。不做
AI 聊天 / 报告 / 模型配置外部模型调用、凭据、成本单独评审。不做

08资料、备份、安全

8.1 资料库与第三方归档（建议）

  • 本人资料库（§6.7：手动文件 / 链接 / 文本笔记）与第三方许可归档分开管理；前者是用户自有内容，后者仅在许可允许时落盘。
  • 第三方归档目录与 SQLite 库分离，便于单独校验与备份；非许可内容只保留元数据与引用，不私自缓存全文。

8.2 一致性备份（建议）

  • 备份范围：本地 SQLite 库（含资料、指标、标签、看板配置）+ 已允许归档的文件 + 本地配置 + 备份清单（逐项 hash）。
  • 本期无 AI 密钥、无登录；条件新闻（如 GNews）若启用，用户自有免费 key 由系统凭据库管理、不进入普通备份；换机 / 恢复后由用户重新输入，本方案不另建密钥备份。
  • 隔离范围仅限受来源限制的第三方负载：本人草稿 / 正文内批注、笔记与自有资料不属于受限负载，正常备份、正常恢复，不因个别第三方条目受限而整包拒绝。
  • 新备份排除：生成新备份时，已标记受限 / 依法应删除的第三方负载不进入新快照。
  • 旧备份恢复过滤：旧快照可能仍含已撤销的第三方负载；恢复时先与独立累积的受限清单比对，仅命中项隔离不复活，其余内容照常恢复，而非假定旧包全部合法。
  • 受限清单独立于备份快照保留当前累积内容（内容 hash + 来源 + 撤销事件指针）；恢复旧包前取当前清单与旧包记录的并集。清单丢失 / 新机恢复时不整包拒绝：本人草稿 / 批注、笔记与自有资料照常恢复，仅把许可无法确认的第三方负载隔离，其余内容切换。
  • 备份为一致性快照：清单记录每个文件的 hash，恢复前先核对清单与实际文件一致。

8.3 恢复流程（建议，不默认合并覆盖）

  • 重复导入 / 重复恢复按内部 ID + hash 幂等处理，不产生重复记录。
  • 清单丢失 / 新机：本人草稿 / 批注、笔记与自有资料照常恢复，仅隔离许可无法确认的第三方负载，其余切换，不整包拒绝。
  • 备份 hash 失败或不兼容时拒绝恢复，并完整保留原库，不做部分写入。

8.4 安全（建议）

  • 数据默认留在本机，不上传本人判断与研究资料；本期无 AI 密钥、无登录、无云端同步；本地搜索只在本机进行，不送 Algolia、不与 Web 端互通。
  • 原生权限按命令最小授予，沿用现有严格 CSP；采集网络访问限定在已登记来源；条件新闻自有 key 由系统凭据库管理，不进普通备份、不另建密钥备份，换机后由用户重新输入。

09分阶段实施与可观测验收

本轮只产出方案，不进入实现；以下阶段与验收均为建议，须经 §10 明确确认后才实施。P00 为已具备的事实基线，计划实施阶段为 P01–P13（共 13 个），总览图展示 P00–P13 共 14 个节点。编号是计划编排顺序，不强制开发排队：本地写作各带真并行，分源接入彼此独立可停；条件源（P12）不承诺必达。外部自动需求在来源未核定前统一保留降级验收行，不留空；A 股 / 港股 / 非上市未核定源维持"条件探索 / 未自动覆盖"，不纳入本次必达阶段。不预设工期与人力。

P00 · 现有骨架（已具备，事实基线）

依赖：无（基线）｜可停止点：基线与回归门始终通过即可。

  • 交付物：桌面工作台与手动 DCF 可运行，原生连接三态可检查；作为后续所有阶段的只读基线与回归门。
  • 范围 / 不做：维持现有隔离边界，不新增网络 / 文件权限；P 编号是计划编排顺序，不代表串行开发排队。
  • 验收成功：pnpm test、types:check、桌面前端构建通过；Tauri 窗口返回 native，浏览器预览返回 browser 且明确提示"原生功能仅在 Tauri 窗口中可用"。
  • 验收边界：回归门失败时暂停后续阶段，先修复基线，不在基线上叠加新功能。

P01 · 本地存储与迁移安全（建议，技术地基）

依赖：P00｜可停止点：迁移与窄命令合同稳定后即可停，本阶段不供日常研究使用。

  • 交付物：Rust 窄 Tauri 命令通道 + SQLite（SQLx）：迁移脚本与命令接口合同先行定义；capabilities 维持 core:default 最小授予；浏览器预览不伪装原生。
  • 范围 / 不做：只做存储与迁移底座，不含业务页面；技术地基阶段，标"不供日常使用"。
  • 验收成功：库读写与迁移可重复跑且结果一致；迁移 / 命令合同文档化，后续阶段按合同接入。
  • 验收边界：迁移校验不一致时拒绝启动并保留旧库文件；不新增网络权限。

P02 · 基本备份 / 恢复（建议）

依赖：P01｜可停止点：代表夹具往返验证通过即放行后续阶段，不等全模块。

  • 交付物：数据库 + 附件通用清单的一致性备份：逐项 hash、暂存预览后切换、不合并覆盖、重复导入幂等。
  • 范围 / 不做：用含库 + 附件的代表夹具做往返验证与 hash / 不兼容失败验证后放行 P03；不说"空库已验证所有真实模块"——后续每新增实体自带备份回归。第三方受限负载的三分支完整验收不在本阶段，放 P09。
  • 验收成功：夹具备份 hash 校验通过，暂存预览无误后切换，原库留回滚副本。
  • 验收边界：人为破坏 hash / 注入不兼容结构时拒绝恢复并完整保留原库，不做部分写入。

P03 · 公司 / listing 档案（建议）

依赖：P01 + P02 安全放行后开始｜可停止点：档案可建档查询即停。

  • 交付物：自由文本建公司、内部独立公司 ID、listing 多证券（A / H / ADR）、公司列表与搜索。
  • 范围 / 不做：不自动归并重名公司；不接行情。
  • 验收成功：建档生成内部公司 ID，同一公司可挂多个证券；代码重复不阻断建档。
  • 验收边界：重名 / 重复代码仅提示人工确认，不静默合并；本阶段完成后该实体自动进入下一次 P02 式备份回归。

P04 · 资料库（建议）

依赖：P03 + P02｜可停止点：资料可管可预览即停，与 P05 / P06 并行不互等。

  • 交付物：手动文件 / 链接 / 文本笔记、标签、本地预览边界（PDF / 图片 / TXT / MD，CSV 带列映射导入）、内部复制 vs 外部引用规则。P04 / P05 / P06 为功能实现独立并行；数据库追加迁移集中串行合并与回归。
  • 范围 / 不做：不做全文搜索引擎；不解析不支持的格式。
  • 验收成功：内部复制的资料在原件改名 / 迁移后仍可预览；标签搜索本机可用。
  • 验收边界：外部引用失效时提示重新定位；不支持形式只留元数据与入口；完成后自带备份回归。

P05 · 自由判断 / 历史（建议）

依赖：P03 + P02（证据可选，不依赖 P04）｜可停止点：判断链可用即停。

  • 交付物：判断草稿自由正文（可选提纲块）、自动保存仅限草稿与正文内批注、转正式仅追加、时间线排序、版本差异、修订复制新版本。证据引用接口预留且可空，不提前堆叠公告 / 新闻表。
  • 范围 / 不做：不设强制 Comment / Draft / Official 三流；缺证不阻断转正式。
  • 验收成功：转正式后旧版只读，修订得到 v2，正式版本间可查看差异。
  • 验收边界：模拟自动保存失败后正文不丢字、显示失败 / 可重试状态并可手动重试，离开 / 切换前给出未保存提示；完成后自带备份回归。

P06 · 手工财务与指标（建议）

依赖：P03 + P02（不依赖 P04 / P05）｜可停止点：手工财务与观测可用即停，自动采集待 P10 起。

  • 交付物：FinancialFact 手工录入（币种 / 单位 / 期间 / 口径 / 审核状态）；内置原始映射 + 固定纯函数派生（§6.6 清单）；自定义数值 / 文本 Observation；待核视图灰显、缺值断点不连线。
  • 范围 / 不做：不做用户公式 DSL；不跨准则强行可比。
  • 验收成功：缺失字段留空不当 0；未审核值默认不进已审核趋势；数值指标进趋势、文本仅卡片。
  • 验收边界：口径缺失的内置指标当期不展示，不编造；完成后自带备份回归。

P07 · 指标看板（建议）

依赖：P03 + P06 即可验收｜可停止点：看板可用，形成无网络闭环。

  • 交付物：模板卡片显隐 / 排序 / 公司分组、所选指标入卡、时间范围、待读 / 待补、最近正式判断；配置存 SQLite 进备份、重启保持。"最近正式判断""待读"等卡片在 P05 / P04 可用时接上。
  • 范围 / 不做：不做任意拖拽低代码平台；P04 / P05 尚未完成时，缺依赖卡片显示空态，指标选择 / 趋势 / 重启保持仍可正常验收，不整体卡住看板。
  • 验收成功：自定义指标与卡片配置重启后保持；缺依赖卡显示空态引导而非报错。
  • 验收边界：无数据时空态引导，不制造推荐内容；完成后自带备份回归。

P08 · 来源登记 / 凭据 / 手动采集通道及任务状态（建议）

依赖：P01 + P02 + P03（可与 P04–P07 独立推进）｜可停止点：闸门与任务状态契约稳定即停。

  • 交付物：统一 CollectionRun 状态机（排队 / 运行 / 成功 / 失败 / 跳过及原因）、准入登记与凭据管理、单次手动队列 / 限额 / 重试幂等契约；条件源自有 key 入系统凭据库。P10 / P11 / P12 只注册适配器，不各自另建队列。
  • 范围 / 不做：不默认启用任何外部源；key 不进普通备份、不另建密钥备份。
  • 验收成功：无登记依据的任务被跳过并记录原因，不伪装已归档；同一任务重复运行幂等去重。
  • 验收边界：许可缺失连元数据也不自动取，仅人工书签并留痕。

P09 · 第三方存储边界与备份恢复校验（建议）

依赖：P02 + P08｜可停止点：落盘准入与三分支恢复演练通过即停。

  • 交付物：源数据落盘准入测试（许可允许才落盘原文，否则 metadata_only）；最小 Takedown 留痕（TakedownEvent、restricted 指针）；受限清单独立累积；备份 / 恢复三分支完整验收（hash 通过先隔离受限项其余切换；清单丢失 / 新机个人内容照恢复；hash 失败 / 不兼容拒绝保留原库）。
  • 范围 / 不做：不做日常审批中心；不等源数据已进入后才补安全。
  • 验收成功：新备份不含已标记受限负载；旧包恢复命中项不复活，个人草稿 / 批注 / 资料照常恢复。
  • 验收边界：清单丢失 / 新机时不整包拒绝，仅隔离许可无法确认的第三方负载。

P10 · SEC 财务（建议，须确认后实施）

依赖：P06 + P08 + P09｜可停止点：SEC 财务单独验收通过即停，不与公告 / 新闻绑定。

  • 交付物：companyfacts 只读试点：少量关注 CIK、UA 声明（名称 + 联系邮箱）、低于平台上限的串行请求与退避；结构化值人工审核入库；published_at / first_seen_at、修订版本全保留。
  • 范围 / 不做：不强求 10-Q；不取第三方附件；不承诺接入成功；作为 P08 队列的一个适配器注册，不另建队列。
  • 验收成功：按登记等级取到结构化候选，带来源 / hash；重复运行幂等。
  • 验收边界：本机不通 / 被限频时保持手工录入，不降级冒充自动成功；companyfacts 缺标签只表示该申报未提供，不等于公司未披露。

P11 · SEC 公告（建议，须确认后实施）

依赖：P04 + P08 + P09｜可停止点：独立可停，不阻塞 P10 / P12。

  • 交付物：submissions 公告列表 + /Archives 原文：许可允许时落盘，否则 metadata_only；幂等去重；人工审核后回流资料库。
  • 范围 / 不做：不把 URL + hash 称全文快照；作为 P08 队列的一个适配器注册。
  • 验收成功：公告候选按时入列并带来源 / 时间 / hash。
  • 验收边界：第三方附件权利不足时只存元数据并标注缺口。

P12 · GNews 条件新闻（建议，须确认后实施；不承诺必达）

依赖：P04 + P08 + P09 + 个人用途确认 / 自有免费 key / 逐源许可前提｜可停止点：条件阶段，可长期停留手工态；成功与否不阻塞 P10 / P11。

  • 交付物：前提全满足后，按 P08 共享队列与配额（100 请求 / 日、12h 延迟、30 天可检索历史窗口）取短摘录，默认 metadata_only。
  • 范围 / 不做：不永久全量存档；"短期 / 元数据、非全量"是保守产品建议，非条款原文许可；作为 P08 队列的一个适配器注册。
  • 验收成功：前提满足后按队列取到短摘录并带来源链接。
  • 验收边界：前提任一不满足即不启用，新闻保持手工链接并显式标注"未自动覆盖"，不静默掉线。

P13 · 应用运行时调度恢复（建议）

依赖：P08 + 至少一个已验收的 P10 / P11 / P12 适配器｜可停止点：调度与失败恢复收敛即停。

  • 交付物：应用运行时到期补抓、退出 / 崩溃后再启动重排队、任务错误原因可见、手动重试不无限。不固定强制依赖某一适配器：建议以已验收的 SEC 公告（P11）作样例验证；未就绪时调度延后，但手动取数仍可用。
  • 范围 / 不做：不开后台常驻服务 / 开机自启；不要求 GNews 成功，不被三项全阻塞。
  • 验收成功：退出 / 崩溃后再启动，错过任务重新排队。
  • 验收边界：任一适配器失败不阻塞其余；调度未就绪期间手动取数不被阻断。
未核定源与后置项（不纳入本次必达阶段）：A 股 cninfo（条件探索，默认不开启）、港股 HKEXnews（通道许可未核定）、非上市来源分流维持原文口径，均需用户单独批准后才接入，手工录入 / 导入 / 人工链接不替代自动采集验收；未批准项保留降级验收行并显式标注。付费数据源、自定义数据源、AI 聊天 / 报告 / 模型配置、行情 / 自动估值按 §7.3 接口边界后置，不排期、不进 P01–P13。

9.1 可观测（建议）

  • 本地可见：采集任务运行记录、失败原因、跳过（许可不足）原因、备份清单校验结果；不依赖远端监控。
  • 本期不设业务指标与灰度；基线未知时先定义口径，不承诺数值提升。
