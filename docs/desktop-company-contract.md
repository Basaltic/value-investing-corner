# P03 公司与证券档案合同

## 已实现范围

- 桌面导航新增“公司研究”。公司列表、名称/证券代码搜索、新建公司、详情与添加证券。
- 公司名称必填；分类为 A 股、港股、美股、非上市；注册地及首条证券可选。
- 公司与证券分别使用内部 UUID，不以公司名称或 ticker 作为主键。
- 一家公司可挂多条证券。证券按 A / HK / US 市场保存代码、交易所、证券类型；非上市档案可无证券。
- 本期不编辑、删除、归并已有公司，不接入行情、资料、判断、指标或 AI。

## 存储与迁移

数据库升级到 schema v2，增加 `companies` 和 `listings`；证券外键引用公司。

1. 启动先只读核对已有数据库版本与 metadata，拒绝未来版本与不一致库。
2. v1 升级前以 `VACUUM INTO ?` 创建同目录 `research.v1-backup.sqlite3`，包含已提交 WAL 数据。不覆盖已有升级备份；若目标已存在，拒绝继续升级，保留原库并报错。
3. 事务执行 v2 迁移，失败回滚；旧数据不丢弃。
4. 新库直接执行 v1 和 v2；v2 重启不重复迁移。
5. 当前 schema 与 metadata 必须一致。数据库路径只由原生应用数据目录决定，前端不能指定。

## 输入与重复信息

- Rust 再次校验输入：名称 1–200 字，注册地最多 200 字；证券代码 1–64 字、交易所和证券类型各最多 100 字；拒绝控制字符，去除首尾空格，证券代码统一大写。
- 同名公司（大小写不敏感）、同市场同代码、同次输入重复证券均先返回 `needs_confirmation`，不写入。
- 界面显示已有档案入口、重复原因与“确认仍然保存 / 取消本次保存”。确认后新建独立记录，不自动合并；取消保留输入。
- 提交及确认期间禁用本表单，防止连续点击；失败显示错误并保留输入。
- 所有 SQL 使用参数绑定。搜索中的 `%`、`_`、反斜杠作为文字处理，不允许用户输入改变 SQL 或成为通配符。

## 窄 Tauri 命令

- `company_create({ input, confirmDuplicates })` → `SaveResult<Company>`
- `company_list({ query })` → `Company[]`
- `company_get({ id })` → `Company`
- `listing_add({ companyId, input, confirmDuplicates })` → `SaveResult<Listing>`

返回保存状态为 `saved` 或 `needs_confirmation`。`Company` 含基础字段、创建时间和 `listings`；详情不存在时返回明确错误。

这些命令只访问原生状态中绑定的数据库，不接受 SQL、文件路径或远程地址。Tauri capabilities 与 CSP 不变，仍仅 `core:default`，不新增网络/fs/shell 插件。浏览器预览禁用本地档案读写，明确显示能力边界；不写 localStorage 替代原生数据库。

## 备份兼容

- 备份格式仍为 v1，schema 支持 1–2；先核对清单与负载真实版本，再在暂存目录升级旧版，不改源备份或当前库。
- v2 备份中公司与证券的 UUID、关联、字段与数量往返一致，重复恢复不增加记录。
- 每个后续实体仍须独立增加备份回归；本阶段不声称提供用户备份界面。

## 验证范围

- Rust：独立 ID、多证券、重启读取、中英文名称/代码搜索、重复拒绝与确认、不自动归并、空名称/非法证券/不存在父公司、事务无部分记录。
- 迁移：v1 数据和升级前快照保留、冲突 schema 迁移回滚、不一致/未来版本拒绝。
- 备份：公司与证券往返，旧 v1 备份只在暂存升级，原备份版本不变。
- Tauri IPC：调用真实命令包装/JSON 解析/响应，连接真实测试 SQLite；运行时仅使用 Tauri MockRuntime，不冒充原生窗口。
- 桌面原生实看：独立验收标识的 debug `.app`（不修改正式配置），建档、同名确认、同公司两证券、退出重启、证券代码搜索。
- 浏览器：公司页面真实渲染，本地按钮和搜索禁用，说明文字清晰。
