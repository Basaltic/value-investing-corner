# P02 基本备份与恢复合同

## 范围

本阶段验证通用的“数据库 + 附件目录”一致性快照，不声称已经覆盖尚未实现的公司、资料、判断、指标等真实业务实体。后续每新增实体，都必须复跑相同的备份回归。

本阶段不处理第三方受限负载与撤销清单；该能力按方案保留到 P09。

## 备份包

每次备份生成一个独立目录：

```text
<backup>/
├── manifest.json
└── payload/
    ├── research.sqlite3
    └── attachments/...
```

`manifest.json` 至少包含：

- 格式版本 `format_version`，当前为 `1`；
- 数据库 schema 版本；
- 每个负载文件的相对路径、字节数和 SHA-256；
- 路径统一使用 `/`，且只能位于 `payload/` 下。

## 创建备份

- 输入为受信任的应用数据目录和目标备份目录；不通过前端接受任意文件路径。
- SQLite 使用 `VACUUM INTO` 生成包含已提交 WAL 内容的一致副本，不能只复制主库文件。
- 附件按相对路径复制到 `payload/attachments`。
- 先写临时目录，清单与负载全部完成后再原子切换为目标目录。
- 目标已存在时拒绝覆盖。

## 预览与恢复

- 恢复前先解析清单并拒绝未知格式版本、绝对路径、父目录穿越、重复路径和未声明文件。
- 逐项校验文件大小和 SHA-256；任一项不符即拒绝，不写入当前数据目录。
- P07兼容schema1–6（format仍1），看板分组/公司顺序、卡片指标锚点/显隐/排序/日期/待核配置和配置revision、待读/待补及完成状态进入备份；恢复往返测试保留，旧版本仅staging升级不改源包。未增加用户备份界面或P09第三方恢复规则。
- P06支持schema v1–v5（格式仍v1），新增财务原始版本、指标定义、观测版本、派生快照及输入引用全量往返回归；恢复旧版仅在staging升级，原备份不修改。旧资料/判断备份测试保留，不恢复未保存的WebView localStorage副本。
- P03起支持schema v1–v2，P04至v1–v3，P05扩展至v1–v4：恢复时先只读检查数据库实际版本与清单一致，再仅于暂存目录执行旧版升级；原备份不修改。P04资料正文/链接/标签/归档/CSV映射/资料ID及复制件往返测试继续保留，外部引用只恢复位置、不包含原件。P05新增已存草稿正文/修订原因/基版与正式版本链往返测试；WebView localStorage中的未保存恢复副本不在database/attachments基本备份内。
- 将负载恢复到同级暂存目录，再初始化数据库以校验 schema 兼容性。
- 校验通过后，将当前数据目录改名为回滚副本，再把暂存目录切换为当前目录。
- 切换失败时尝试恢复原目录；不做部分合并。
- 对已经恢复到相同内容的备份再次恢复，不产生重复数据；每次成功切换只保留本次回滚副本。

## P02 验收

- 含实际 SQLite 数据与至少一个附件的代表夹具能完整往返。
- WAL 中已提交但尚未 checkpoint 的数据也进入备份。
- 清单 hash 或字节数被破坏时拒绝恢复，当前数据保持不变。
- 未知备份格式或未来数据库 schema 被拒绝，当前数据保持不变。
- 成功恢复后，原数据目录作为回滚副本保留。
- 重复恢复结果一致，不产生额外业务记录。
- 未新增 Tauri 文件、网络或 shell 插件权限。
